Introduction

Back-of-the-envelope estimation is a crucial skill in system design interviews. It involves making quick, rough calculations to assess system capacity or performance. According to Jeff Dean, Google Senior Fellow, these estimates help evaluate whether designs meet requirements through thought experiments and common performance benchmarks.

This chapter covers key concepts, methodologies, and examples to build proficiency in scalability and estimation.

Latency Numbers Every Programmer Should Know

Latency numbers represent the time taken for various operations in computing systems:

OperationLatency (2020)
L1 cache access0.5 ns
L2 cache access7 ns
Main memory access100 ns
SSD random read150 µs
HDD random seek10 ms
Round-trip in data center500 µs
Inter-region data center150 ms

Key insights:

  • Memory is fast, disk is slow.
  • Avoid disk seeks whenever possible.
  • Compress data before transmitting over the internet to save bandwidth.

Availability Numbers

High availability (HA) ensures minimal downtime. Availability is expressed in nines:

  • 99% (two nines): ~3.65 days/year downtime
  • 99.9% (three nines): ~8.8 hours/year
  • 99.99% (four nines): ~52 minutes/year
  • 99.999% (five nines): ~5.3 minutes/year
  • 99.9999% (six nines): ~31.56 seconds/year

Cloud providers like Amazon, Google, and Microsoft aim for SLAs of 99.9% or higher.

Section 2: Example — Twitter QPS and Storage

Assumptions

  • 300 million monthly active users (MAU)
  • 50% daily active users (DAU)
  • 2 tweets per user per day on average
  • 10% of tweets contain media
  • 5 years data retention

Estimations

  1. Queries per second (QPS):
    • DAU = 300M × 50% = 150M
    • Tweets QPS = 150M × 2 / 24h / 3600s ≈ 3,500
    • Peak QPS ≈ 2 × 3,500 = 7,000
  2. Media storage:
    • Tweet size: tweet_id 64 bytes + text 140 bytes + media 1 MB
    • Daily media storage: 150M × 2 × 10% × 1 MB = 30 TB/day
    • 5-year storage: 30 TB × 365 × 5 ≈ 55 PB

Section 3: Tips for Effective Estimation

1. Rounding and Approximation

Precision is not critical; focus on the process. Simplify with round numbers — e.g. 99987 / 9.1 ≈ 100,000 / 10 = 10,000.

2. Write Down Assumptions

Document assumptions clearly for reference during the interview.

3. Label Units

Avoid ambiguity — write 5 MB instead of 5.

4. Common Estimation Scenarios

  • QPS: Traffic intensity
  • Peak QPS: Traffic spikes
  • Storage: Total data needs
  • Cache: Memory for caching
  • Number of servers: Hardware from workload
